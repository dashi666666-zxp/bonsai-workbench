# 记忆分层与联网搜索（0.6.0）

两个都是「让 27B 少犯傻、少重复问」的低成本补强：记忆分层解决**跨会话记不住**，联网搜索解决**只有 Bing 通、还要先白等 DDG 超时**。

## 1. 记忆分层

### 1.1 为什么不向量化

27B 常驻已占 7.6/8.15 GB 显存，再挂 embedding 模型会抢显存（同 RAG 的取舍）。所以记忆是**本地纯文本文件**：无向量库、无嵌入调用、无额外进程。检索用字面匹配（大小写不敏感），足够覆盖「项目约定 / 偏好 / 结论」这类短条目。

### 1.2 五层

| target | 文件 | 是否自动注入 | 用途 |
| --- | --- | --- | --- |
| `user` | `<BW_DATA>/memory/user.md` | ✅ | 用户长期偏好（语言、风格、习惯） |
| `memory` | `<BW_DATA>/memory/memory.md` | ✅ | 全局环境事实（显卡、模型、路径） |
| `key` | `<BW_DATA>/memory/key/<workspace-slug>.md` | ✅ | **当前工作区**的关键结论与约定 |
| `project` | `<BW_DATA>/memory/project/<workspace-slug>.md` | ❌ | 项目日志，按需检索 |
| `daily` | `<BW_DATA>/memory/daily/YYYY-MM-DD.md` | ❌ | 每日 run 摘要，自动写、30 天自动清 |

- `<workspace-slug>` = 工作区目录名净化 + sha1(绝对路径小写) 前 8 位，跨项目不串。
- 条目格式固定单行：`- [YYYY-MM-DD HH:MM] 文本`。单条正文上限 2000 字，每层最多 400 条（超出丢最旧）。
- 写入目录可用 `BW_MEMORY_DIR` 覆盖，便于测试隔离。

### 1.3 注入规则（每回合都吃 token，所以有硬上限）

- 只注入 `user` / `memory` / `key` 三层；`project` / `daily` 只在用 `memory` 工具检索时出现。
- 逐层上限：user 500 / memory 700 / key 900 字符；总上限 `injectMaxChars`（默认 2200）。超了从最旧条目开始丢，再超就整体截断并标「已截断」。
- **记忆全空 → 注入空串 → 一个字都不花**。
- **空库提示（0.7.1）**：三层都空时 `memoryEmptyHint(cfg)` 会在 `promptExtra` 末尾补一行「记忆库还空着：本轮若出现长期有用的事实……用 memory 工具写入 user/memory/key 层，下一轮会自动注入；一次性细节不写」。这一行解决「机制在、没人喂」——模型不会主动想到调 `memory`。实测空库跑一轮「记住 4790 端口」：模型自调 `memory` 写入全局层，`injectChars` 0 → 172；有记忆或 `memory.enabled=false` 时不加。
- 注入块拼在 system prompt 的 `promptExtra` 里（摘要块、思考计划块、RAG 资料块之后），由 `model/agent.mjs` 每步组装。

### 1.4 自动每日日志

每个 run 结束（`run_end` 之后、插件钩子之后）写一行：

```
<任务前 80 字> → done|error|stopped（N 步，X s，r_xxx）
```

写失败不影响 run 本身（`appendDaily` 内部吞异常返回 false）。`memory.daily:false` 可关；启动时 `pruneDaily(30)` 清 30 天前的日志。

### 1.5 工具与权限

工具名 `memory`，`risk: 'write'`（只读档拒绝、workspace-write 档按 `args.path` 判——记忆工具不带 path，因此放行）。风险项已登记在 `model/permission.mjs` 的 `RISK` 表。

```
memory(action='add'|'list'|'search'|'remove', target?='key', content?, query?, match?, limit?)
```

- `add`：`content` 不能为空；
- `remove`：`match` 必须是唯一子串，多条命中直接报错（不会误删）；
- 记忆关闭时工具直接返回「记忆已关闭（设置 → 记忆分层 里可开启）」，不会静默成功。

### 1.6 API 与 UI

- `GET /api/memory`：完整快照（五层文件、条数、字符数、预览、注入块与注入字符数）。
- `GET /api/state` 里的 `memory`：轻量版（dir/slug/enabled/injectChars/各层 count+chars），供状态行渲染。
- 设置面板「记忆分层」段：开关、每日日志开关、注入上限、状态行、`查看记忆`（拉 `/api/memory` 贴五层预览）。

## 2. 联网搜索

### 2.1 现状（0.6.0 前）

`model/search.mjs` 已经能搜：DDG HTML → DDG API → Bing HTML 三级回落，`unwrapBing` 解 `/ck/a?u=...` 跳转，`formatResults` 统一成「搜索「q」· 来源 x · N 条」+ 摘要 + 提示用 `web_fetch`。问题是**每轮都先撞 DDG 超时**（本机约 10.5 s），只有 Bing 通。

### 2.2 0.6.0 的三条改动

1. **引擎可选**：`webSearchEngine: 'auto' | 'bing' | 'duckduckgo'`。`auto` 下先试上次成功的引擎（sticky），失败才换；显式点名则只打这一个（失败直接报错，不静默换后端）。
2. **短超时**：`auto` 下 DDG 只给 6 s（不设超时的请求会白等到 12 s），Bing 用完整超时。
3. **5 分钟缓存**：同一 query+count 命中缓存直接返回，`formatResults` 头部标「（缓存）」；上限 32 条，`resetSearchState()` 供测试清空。

### 2.3 本机网络真值

- DDG / Brave / Searx 全 `fetch failed`（约 10.5 s 超时）；**只有 Bing 通**（`setlang=zh-CN&count=20`，200 / 约 104 KB / 10 条）。
- Bing 中文泛查询质量一般，属对方语义问题；精确型号/英文关键词效果可用。

## 3. 边界

- 记忆是**字面检索**，同义改写搜不到（例如存「pnpm」搜「包管理器」不可得）。要语义检索得引入向量库，与本机显存取舍冲突，不做。
- 注入只覆盖三层且总长 2200 字符：条目多了要自己整理（`remove` 或改写）。
- `project` / `daily` 不进注入，模型需要时必须主动调 `memory(action='search')`。
- 搜索缓存只在进程内，重启即失；不落盘是为了避免陈旧结果污染答案。
- 记忆工具写入的是文件，`workspace-write` 档下写 `<BW_DATA>` 不在工作区内——当前实现按「无 path 参数即视为工作区内」放行；若以后把记忆根改到工作区外可写位置需重新评审这一条。

## 4. 复跑

```bat
node test\smoke.mjs                                  :: 202 项（含记忆 30 项、搜索后端 6 项）
node _scratch\live_probe_060.mjs                     :: 23 项真机端到端（生产 4790，真实 27B）
node _scratch\ui_probe_060.mjs                       :: 18 项 UI（无头 Edge + CDP）
curl http://127.0.0.1:4790/api/memory                :: 五层快照
curl http://127.0.0.1:4790/api/state | findstr memory
```

真机端到端：让模型「记住 本项目用 pnpm」→ 新会话问「本项目包管理器」→ 应能直接答出 pnpm（写入 key 层并被注入）。`live_probe_060.mjs` 实测 23/23：run1 自调 `memory` 写 key（文件含 pnpm）、run2 不调工具直接答 pnpm、run3 `web_search` 走 bing 且返回条数、三次 run 后 daily ≥3 条且带 runId；`ui_probe_060.mjs` 实测 18/18：设置面板搜索后端/记忆分层段回填、「查看记忆」出五层预览、控制台 0 报错（截图 `_scratch/ui60-settings.png`）。
